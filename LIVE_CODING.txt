LIVE CODING — ПЛАН
Приложение готово. Пишем только тесты: открываем workshop-файл, выделяем "// region Step N",
Cmd + / , запускаем тест из гаттера. Эталон лежит рядом (тот же класс без слова Workshop).

==================================================================================
КОМАНДЫ (терминал Android Studio, корень barista/)
==================================================================================
./gradlew moats                        все быстрые рвы: detekt + konsist + граф модулей + unit/UI тесты
./gradlew screenshots                  сверить скриншоты с golden
./gradlew recordScreenshots            перезаписать golden
./gradlew :konsist-test:test --rerun-tasks       только архитектурные тесты
./gradlew assertModuleGraph            только граф модулей
./gradlew :feature:menu:testDebugUnitTest --tests "*MenuViewModelTest"      один класс
./gradlew :app:installDebug            поставить приложение на эмулятор
./gradlew moats -q --console=plain     как запускает агент: пусто = ок, exit code = ответ

Диф скриншота после падения:  <module>/build/outputs/roborazzi/<имя>_compare.png
Запуск с adb:  adb shell am start -n ru.otus.barista/ru.otus.barista.app.MainActivity

==================================================================================
ШАГ 0. Тур по приложению (3 мин)
==================================================================================
Запустить app. Показать: happy hour у Капучино (-15%), Айс латте внизу (sold out),
чипы и поиск "мат", сердечко, экран напитка (размер, добавки, "Максимум 3"),
Отладка -> Fail next request -> pull-to-refresh -> баннер "Нет связи".
  где:  settings.gradle.kts                      — модули: data/{api,impl}, domain/{api,impl}, feature/*, core/*
        feature/menu/src/main/kotlin/ru/otus/barista/feature/menu/   — только presentation / ui / navigation / di
        app/src/main/kotlin/ru/otus/barista/app/di/AppGraph.kt      — единственное место, где собираются все impl

==================================================================================
ШАГ 1. Unit: чистый use case — формула цены (4 шага)
==================================================================================
Что: цена = база x размер + добавки, потом скидка, округление один раз. Без единого дабла.
Зачем: самый дешёвый ров; имя теста = WHEN ... SHOULD ..., Arrange/Act/Assert пустыми строками.
  пишем:  domain/impl/src/test/kotlin/ru/otus/barista/domain/impl/workshop/CalculatePriceUseCaseWorkshopTest.kt
  код:    domain/impl/src/main/kotlin/ru/otus/barista/domain/impl/usecase/CalculatePriceUseCaseImpl.kt

==================================================================================
ШАГ 2. Unit: use case с фейком репозитория (4 шага)
==================================================================================
Что: FakeMenuRepository (DTO) + FixedClock -> happy hour; sold out последний; избранное смёржено.
     Шаг 4 — тот же тест на MockK: длиннее и ломается при рефакторинге.
Зачем: фейки вместо моков; use case'ы компонуются; маппер DTO -> domain виден в деле.
  пишем:  domain/impl/src/test/kotlin/ru/otus/barista/domain/impl/workshop/GetMenuUseCaseWorkshopTest.kt
  код:    domain/impl/src/main/kotlin/ru/otus/barista/domain/impl/mapper/DrinkMapper.kt
  фейки:  core/testing/src/main/kotlin/ru/otus/barista/core/testing/   (FakeMenuRepository, FixedClock, Create)

==================================================================================
ШАГ 3. Unit: ViewModel как state machine (5 шагов)
==================================================================================
Что: Loading -> Content; Empty(NO_FAVORITES); Error -> Retry; debounce поиска на виртуальном времени; событие OpenDrink.
Зачем: фича видит только интерфейсы use case -> тестируем с фейковыми use case, не с репозиторием.
     "Этот файл человек читает вместо ViewModel".
  пишем:  feature/menu/src/test/kotlin/ru/otus/barista/feature/menu/workshop/MenuViewModelWorkshopTest.kt
  код:    feature/menu/src/main/kotlin/ru/otus/barista/feature/menu/presentation/MenuViewModel.kt
